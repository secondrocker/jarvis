# 项目中文注释与 README 中文化设计

## 目标

将项目自有代码中的英文注释统一调整为中文，并为关键职责、接口边界和复杂流程补充必要的中文注释；同时将根目录 `README.md` 的说明文字完整调整为中文，使中文开发者能够快速理解项目结构、执行流程和维护约束。

## 修改范围

本次处理以下文件：

- `src/agent_app/**/*.py`：业务源码中的模块、类、函数 docstring 和行注释。
- `tests/**/*.py`：测试代码中的模块、测试替身、辅助函数和测试意图注释。
- `scripts/smoke.sh`：冒烟测试脚本中的步骤与前置条件注释。
- `README.md`：标题、架构说明、操作指南、接口说明、测试说明、目录结构和限制说明。

不处理依赖锁文件、项目规格文档、历史计划文档和第三方代码。

## 注释原则

采用“完整中文化 + 关键注释补充”策略：

1. 将范围内已有的英文模块 docstring、类/函数 docstring 和普通行注释翻译为自然、准确的中文。
2. 为缺少说明的核心公共类、公共函数和关键内部流程补充中文 docstring 或行注释。
3. 注释重点解释模块职责、接口契约、设计原因、路由优先级、状态流转、异常降级和测试意图。
4. 不为赋值、简单条件判断、直接返回等显而易见的代码添加逐行注释。
5. 保留 Python 标准工具指令和静态检查标记，例如 `# type: ignore`、`# pragma: no cover`、`# noqa`、`# shellcheck`；如同一行包含解释性英文，则只翻译解释部分。
6. 使用项目既有的简洁 docstring 风格，不引入冗长的参数模板，也不改变代码组织方式。

## README 中文化规则

- 将所有面向读者的英文标题和说明文字调整为中文。
- 保留项目名、库名和标准技术术语，如 FastAPI、LangGraph、Deep Agents、SSE、API、JSON。
- 保留命令、路径、环境变量、HTTP 路径、请求/响应字段、枚举值和示例载荷原样。
- 架构图中的说明性英文标签调整为中文，但代码符号和组件类名保持原样。
- 不改变 README 所描述的功能、限制和操作步骤。

## 行为与兼容性约束

本次变更只涉及注释和文档：

- 不修改任何运行逻辑、类型声明、函数签名或模块导入。
- 不翻译错误消息、日志内容、提示词、API 响应内容或测试断言中的字符串。
- 不修改测试用例行为，不新增运行时依赖。
- 不借机进行无关重构或格式调整。

## 验收与验证

完成修改后执行以下检查：

1. 扫描 `src/agent_app`、`tests` 和 `scripts/smoke.sh` 中的注释与 docstring，人工复核残留英文是否属于必须保留的工具标记、技术名词或代码符号。
2. 运行 Ruff 检查与格式检查，确认 docstring 修改未造成语法或格式问题。
3. 运行完整测试套件，确认纯注释变更没有意外影响代码。
4. 检查 Git diff，确认没有修改运行字符串和业务逻辑，README 的代码示例保持有效。
